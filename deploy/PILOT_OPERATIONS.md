# Slow 邀请制内测运营基线

本流程只适用于小规模邀请制产品验证，不代表公开注册、商业化运营或已经证明长期学习效果。

## 每日巡检

1. 检查 `https://slow.net.cn/api/health`、API/Web/PostgreSQL 容器健康和磁盘空间。
2. 在 API 容器内运行 `python operations_report.py --include-identifiers`，更新受保护的运营台账。
3. 处理失败学习任务、失败 AI 调用和用户反馈；不得在聊天或普通日志中复制用户正文、回答、笔记或凭据。
4. 查看待处理退出申请，优先处理已到 `deletionDueAt` 的账号。

## 每周检查

- 第一节开始率、第一章完成率、整书完成率和 7 天保持概念数；
- 失败任务和用户反馈的共同原因；
- 单用户输入/输出 Token 与按当前供应商单价计算的模型成本；
- 当前 PostgreSQL 备份是否可列出、是否至少完成一次隔离恢复演练。

## 隐私同意

- 生产环境用户必须同意当前版本的隐私告知与自愿参加内测，才能填写画像或进入学习服务。
- 同意记录按 `notice_version + trial_terms_version` 追加保存；告知版本变化后需要重新同意。
- Demo 与开发环境可展示告知，但不把 Demo 行为当作真实试点证据。

## 退出与删除申请

用户在“个人中心 → 账号与数据”输入“退出并删除”后：

1. 服务端创建 `AccountExitRequest`；
2. 用户状态改为 `exit_requested`，账号凭据停用，全部活动 Session 立即撤销；
3. 运营者在 7 日内核对申请，完成活动数据库和附件中的删除或去标识化，并记录处理结果；
4. 备份副本进入受限轮转，当前试点以 14 日为清除目标；任何恢复操作都必须先核对退出台账，不得把退出账号恢复为可用状态。若因安全审计或法律义务必须保留最小事实，只保留去标识化状态与处理依据，不保留学习正文；
5. 完成前不得把请求标记为已处理，也不得重新启用账号。撤回申请必须由用户通过原邀请渠道明确提出并完成身份核对。

当前版本故意不提供公网运营管理 API。账号与退出申请只能通过 ECS 本机命令、数据库只读报告和受保护台账处理，等待平台运营者 RBAC 完成后再迁移到管理界面。
