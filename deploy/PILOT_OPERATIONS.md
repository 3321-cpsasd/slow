# Slow 邀请制内测运营基线

本流程只适用于小规模邀请制产品验证，不代表公开注册、商业化运营或已经证明长期学习效果。

## 每日巡检

1. 检查 `https://slow.net.cn/api/health`、API/Web/PostgreSQL 容器健康和磁盘空间。
2. 在 API 容器内运行 `python operations_report.py --include-identifiers`，更新受保护的运营台账。
3. 处理失败学习任务、失败 AI 调用和用户反馈；不得在聊天或普通日志中复制用户正文、回答、笔记或凭据。
4. 查看待处理退出申请，优先处理已到 `deletionDueAt` 的账号。

## 每周检查

- 第一节开始率、第一章完成率、整书完成率和 7 天保持概念数；
- 失败任务和用户反馈的共同原因；
- 单用户输入/输出 Token 与按当前供应商单价计算的模型成本；
- 当前 PostgreSQL 备份是否可列出、是否至少完成一次隔离恢复演练。

## Alpha 邀请申请闭环

`alpha@slow.net.cn` 是公开的 Alpha 申请入口。生产环境中的注册模式和访问码是唯一权威；
阿里邮箱个人模板只用于提高操作效率，仓库中的
[`templates/alpha-invite-email.txt`](templates/alpha-invite-email.txt) 是邮件文案的权威版本。

当前访问码是共享且可重复使用的，不是单人、单次邀请码。因此必须人工审核申请，
不得配置自动回复，也不得在公开频道、聊天记录、普通日志或工单中粘贴访问码。

每个申请必须按以下顺序处理：

1. **审核来信**：确认收件人为 `alpha@slow.net.cn`，检查发件地址和基本学习意图；
   被误判为垃圾邮件的正常申请先恢复到收件箱。明显滥用、批量索取或来源异常的申请不发送访问码。
2. **发送前检查**：确认 `GET /api/auth/config` 返回 `mode=password`、
   `registrationMode=alpha` 和 `registrationCodeRequired=true`。通过受控运维路径读取当前有效访问码，
   只允许进入权限为 `0600` 的临时文件或受控内存，不得输出到终端。
3. **只回复一封完整邮件**：回复原申请人，使用权威模板并替换 `[ACCESS_CODE]`。
   发送前逐项确认收件人、主题、可点击的 `https://slow.net.cn`、真实访问码、创建账号步骤、
   一次性恢复码提醒和访问码保密说明都在同一封邮件中；确认 `[ACCESS_CODE]` 已完全移除。
4. **发送后清理**：在“已发送”中确认邮件存在；立即删除本机和服务器上的临时访问码副本，
   清空剪贴板和自动化进程中的临时变量。生产配置中的有效访问码保持不变。
5. **完成验收**：申请人使用邮件中的链接和访问码创建账号，保存仅展示一次的恢复码，
   并成功登录后，才把该申请标记为完成。

如果模板正文没有带入、链接不是 `https://slow.net.cn`，或任何必需字段缺失，禁止发送；
应在当前邮件中修正并重新完成整封邮件校验，不得拆成多封补充邮件。访问码一旦疑似泄露，
先轮换生产访问码并验证 API，再继续处理申请。

## 隐私同意

- 生产环境用户必须同意当前版本的隐私告知与自愿参加内测，才能填写画像或进入学习服务。
- 同意记录按 `notice_version + trial_terms_version` 追加保存；告知版本变化后需要重新同意。
- Demo 与开发环境可展示告知，但不把 Demo 行为当作真实试点证据。

## 退出与删除申请

用户在“个人中心 → 账号与数据”输入“退出并删除”后：

1. 服务端创建 `AccountExitRequest`；
2. 用户状态改为 `exit_requested`，账号凭据停用，全部活动 Session 立即撤销；
3. 运营者在 7 日内核对申请，完成活动数据库和附件中的删除或去标识化，并记录处理结果；
4. 备份副本进入受限轮转，当前试点以 14 日为清除目标；任何恢复操作都必须先核对退出台账，不得把退出账号恢复为可用状态。若因安全审计或法律义务必须保留最小事实，只保留去标识化状态与处理依据，不保留学习正文；
5. 完成前不得把请求标记为已处理，也不得重新启用账号。撤回申请必须由用户通过原邀请渠道明确提出并完成身份核对。

当前版本故意不提供公网运营管理 API。账号与退出申请只能通过 ECS 本机命令、数据库只读报告和受保护台账处理，等待平台运营者 RBAC 完成后再迁移到管理界面。
