# ADR-0021：系列内按需知识身份候选与追加式裁决

- 状态：Accepted，第一版薄切片已实现
- 日期：2026-08-15
- 关联：ADR-0012、ADR-0015、ADR-0020

## 背景

默认路线级身份曾按“系列 ID + 冻结目标文本”创建 Concept。这样虽然能够结算段位，却把“解释递归终止”“识别递归边界”“迁移递归到搜索”错误拆成多个知识节点，并把所有目标固定为 `recognition`。用户投影因此只能记住题目文本，不能表达同一知识在不同能力维度上的跨书演进。

不能反过来按名称或文本相似度全局合并。相同名称可能具有不同定义、范围和边界；未经发布的候选也不能静默成为公共知识身份。

## 决策

### 1. 章节规划显式区分知识与能力目标

没有已发布知识清单时，章节规划必须为每节输出结构化 `concept_candidate`，至少包含稳定候选键、名称、定义、范围和边界；每条 objective 另行声明 `recognition`、`mechanism`、`application`、`boundary` 或 `transfer` 维度。

Concept Candidate 只回答“这是什么知识”，objective 与 Assessment Target 回答“本次要验证用户能做什么”。正文中的例子、材料和支撑性关联知识不得因此自动成为考核目标。

### 2. 自动复用只限同一系列的精确语义

服务端对候选键、名称、定义、范围和边界生成确定性语义指纹：

- 同一系列内指纹完全相同的候选复用同一 Concept Revision，因此可以跨书复用同一用户知识节点；
- 同一系列内名称或候选键相同但语义指纹不同的候选保持不同身份，并记录 `unresolved`；
- 不同系列的未发布候选不自动复用，即使指纹完全相同；
- 跨系列复用仍以已发布知识图身份为权威。

该路径属于 ADR-0015 的系列路线级身份，不把候选伪装成已发布公共知识。

### 3. 身份裁决追加记录

每个节级候选写入 `KnowledgeIdentityCandidate`。服务端随后追加 `KnowledgeIdentityDecision`，第一版支持：

- `create_concept`：系列内首次出现精确语义；
- `reuse_revision`：复用同系列精确语义，或逐字引用服务端允许的既有版本；
- `unresolved`：同名或同键存在不同语义，创建独立临时身份并保留比较对象；
- `create_revision`：为后续人工或离线裁决保留，第一版不自动产生。

裁决记录保存规则版本、比较版本、依据、执行者和可选 supersedes 链，不覆盖历史候选或旧裁决。

### 4. 证据与用户投影不按题目文本分裂

不同 Assessment Target 可以绑定同一 Concept Revision，同时保留各自的目标陈述和能力维度。题目与原始观察继续绑定冻结目标；节点段位投影按 Concept Revision 聚合合格证据。

后续公共身份发布或人工裁决不得改写原始证据。若需要把路线级身份迁移到公共身份，必须沿用 ADR-0020 的追加式身份决策与可重建投影边界。

## 第一版边界

本切片只解决候选、身份裁决、跨书复用、能力维度和用户投影的最小闭环，尚不包括：

- 自动生成或发布概念间关系；
- 人工处理 `unresolved` 的管理界面；
- 路线级候选晋升为公共发布知识的工作流；
- 因身份晋升而触发的历史投影重建；
- 基于该投影改造复习选择器和正文生成策略。

在上述边界完成前，不引入图数据库；关系、候选、裁决、证据和投影继续由当前关系数据库承担唯一权威。

## 最低验收

1. 同一系列两本书中的精确候选复用同一 Concept Revision。
2. 机制、边界和迁移目标保留不同 Assessment Target 与维度。
3. 同名不同定义不会自动合并，并产生可审计的 `unresolved` 裁决。
4. 不同系列的未发布候选不会自动复用。
5. 完成后一本书的迁移验证时，证据写回前一本书已经建立的同一知识节点。
6. 候选、裁决、目标、原始证据和用户投影都可以沿稳定 ID 与规则版本追溯。
