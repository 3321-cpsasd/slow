# ADR-0017：独立章节范围审校与知识增量去重

- 状态：Accepted，核心链路已实现
- 日期：2026-08-13
- 关联：ADR-0001、ADR-0014、ADR-0016

## 背景

只检查小节标题不同，不能防止正文实质重复。两个相邻小节可能使用同一套定义、机制和例子，也可能验证同一件事；正文模型随后即使各自正常生成，学习者仍会连续学到高度相似的内容。

这属于章节规划阶段的知识范围分配问题，不应等到正文生成后再靠改写措辞修复。让目录作者自行复核也会形成同一模型的自审，并容易保留原先的范围划分偏差。

## 决策

章节规划默认执行两步：

```text
目录作者模型：生成完整候选小节序列
       ↓
独立范围审校模型：通读整章，接受或最小编辑每一节
       ↓
服务端重建并执行既有课程契约校验
```

目录作者首先为整章分配互斥的知识增量，并逐对比较相邻小节的定义、机制、主要例子和验证目标。若两节依赖同一套核心解释或考核同一件事，共同内容由前一节承载，后一节必须收窄到新的机制、边界或迁移问题。

新增 `curriculum_review` 用途。审校模型看到完整章节候选，但只能：

- 接受小节；
- 最小修改小节的 `title`、`question` 和 `objectives`。

审校模型不能新增、删除或重排小节，不能修改稳定概念键和目标键，也不能扩展章目标。服务端按槽位应用修改并原样保留课程身份；覆盖不完整、槽位重复或无实际变化的编辑均被拒绝。

例如，“CPU 到 GPU 独占的 requests/limits 语义”由前一节负责；后一节不再重复 `nvidia.com/gpu` 的基本申请方式，而收窄到 MIG、time-slicing、显存隔离及其调度边界。

## 独立性与可用性边界

- 审校路由排除实际目录作者的部署及整个模型家族；
- 有合格审校模型时，记录作者、审校者和编辑数量；
- 生产环境中独立模型不可用、独立性不足或审校结果无效时失败关闭，不得发布未审校的新章节目录；
- 测试、开发和显式 Demo 环境可保留原候选并记录 `skipped` 审计，以支持本地开发，但这种候选不得冒充生产审校结果；
- 该审校只判断教学范围与递进，不得被表述为事实核验。

章节目录虽不是评分答案，但它会决定后续教材范围。M4 生产边界因此同样失败关闭；非生产环境的可审计降级只是一种开发便利。测验答案、解锁与掌握证据继续按 ADR-0016 失败关闭。

## 版本边界

范围审校用于新章节规划或显式重规划。已经发布、已经学习或已经产生测验证据的小节不得被静默覆盖；若要修复现有系列，必须创建新的内容/课程版本，保留旧版本及学习证据的可追溯关系。

## 最低验收

1. 审校输入包含完整候选小节序列，而不是逐节孤立调用。
2. 审校只能接受或最小编辑，Schema 不包含稳定 ID、增删或重排能力。
3. 审校不能使用目录作者部署或同模型家族。
4. 生产环境审校不可用时章节生成失败关闭；非生产环境只能以明确的 `skipped` 审计降级。
5. 应用编辑后稳定概念键、目标键、小节数量和顺序不变。
6. 已发布小节不因新规则被静默改写。
