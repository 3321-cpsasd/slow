# ADR-0009：跨知识类型的正文编排与段落职责

- **状态**：Accepted，已实现
- **决策日期**：2026-08-11
- **继承边界**：[ADR-0001](0001-lesson-generation-v2.md)、[ADR-0008](0008-section-continuity-and-recovery.md)
- **取代范围**：ADR-0001 第 6 节中 V2 固定共享槽位的在线生成要求；其余可信发布边界继续有效

## 1. 决策

正文继续以 `ContentBlock` 作为稳定的答疑、反馈、来源、测验证据和版本管理单位。固定的是 Learning Contract、核心正文依据、题目和证据之间的关系；不同知识传统如何解释、举证、比较、推导与练习，由版本化的 `CompositionPolicy` 动态决定。

课程层级仍止于小节。段落职责不是目录、进度、解锁节点或新的考核目标。

## 2. 为什么不按学科套模板

同一学科内部可能同时包含形式推导、因果解释、文本解释、实证比较与规范判断。服务端因此不按“理工、文科、社科”三个书架标签直接选择模板，而从冻结的小节问题、目标、目标维度和验证方式确定认识方式：知识对象、学习操作与证据形式。

当前显式课程元数据不足时，服务端可以使用版本化、可审计的确定性推断作为教学编排依据；推断不得修改 Assessment Target 身份、正确答案、通过门槛或掌握声明。

## 3. 稳定证据骨架

- 每个冻结目标仍对应一个 `Tn_CORE` 核心依据块；
- 必需目标必须同时被正文教授和题目测量；
- 题目只能引用教授同一目标的正文依据；
- 支撑段落不能自行获得考核目标；
- 大型前置缺口继续显式重规划；
- 全部候选继续在同一事务中原子发布。

## 4. 动态支持段落

固定的 `SHARED_EXAMPLE`、`BOUNDARY`、`PRACTICE`、`SUMMARY` 不再是全局发布条件。模型可以按 CompositionPolicy 使用推导、机制、worked example、实证案例、原始文本、证据分析、对照、替代解释、反驳、反例、边界、应用、迁移、练习、综合与过渡等支持段落。

每个块拥有一个主要职责和零到多个辅助教学动作。一个块可以自然地同时举例、比较并揭示边界，不得为了角色数量机械拆块。

职责缺失、未知或暂未被某个界面利用时，只允许降低教学编排与呈现优化，不能绕过证据门禁，也不能让历史内容不可读。

## 5. 案例可信边界

案例必须区分假设情境、实证案例、原始材料案例、worked example、反例与学习者迁移情境。每个案例拥有候选内稳定的 `caseKey`；同一情境跨多个正文块展开时复用同一 Key，最低不同案例数按唯一 Key 校验，不按正文块数校验。实证案例和原始材料需要允许的知识主张或来源；假设情境不得伪装成真实事实，个性化情境不得编造学习者经历。

## 6. 兼容与连续性

V3 使用新的 Pipeline、Schema、Prompt 与规则版本。V5 及更早已发布正文保持不可变并继续可读，不执行自然语言职责回填。

一节缓冲、模型回退、任务租约、`/prepare`、锁定访问、竞态复用和原子发布继续由 ADR-0008 的现有协调器负责。所有模型适配器必须对同一次 V3 生成使用同一协议；恢复流程不得把不同协议或不同候选的半成品拼接发布。

## 7. 发布门禁

继续硬失败：契约外目标、必需目标未教授或未测量、悬空证据引用、来源或知识主张越界、低于 CompositionPolicy 的最低正文块数或不同案例数、案例缺少稳定身份、不可发布布局、部分候选和原子发布失败。

不再硬失败：缺少固定小结块、练习或边界与案例位于同一块、块顺序不同、未知职责的展示优化缺失。

## 8. 最低验收

- 形式推导、文本论证与社会实证样例可解析出不同的编排策略；
- 候选正文无需固定共享槽位也可通过，但每个目标仍必须有唯一核心依据；
- 实证案例与原始材料缺少允许主张时必须整节失败；
- 同一案例拆成多个正文块不能满足多个不同案例的最低要求；
- Ask Me、复习与 Fast View 按目标绑定和显式职责消费新正文，历史正文继续可用；
- 完整后端测试、前端类型检查和生产构建通过，并在真实页面验证职责标签与 Fast View。
