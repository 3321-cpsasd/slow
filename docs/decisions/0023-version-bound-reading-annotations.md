# ADR-0023：正文版本绑定的阅读标注与答疑历史

- **状态**：Accepted，MVP 已实现
- **日期**：2026-08-15

## 背景

Ask AI 是用户遇到疑问时的主要第三方交互入口，但高亮和批注属于用户自发的阅读行为。把三者混成一种“问 AI”操作，会误导用户，也会在正文因反馈而生成新版本时造成更严重的归属问题：原文字段、答疑上下文、测验证据和用户当时写下的批注可能被静默解释成属于新正文。

## 决策

1. 高亮和批注是独立的用户阅读标注层，不调用 AI，不写入掌握度、解锁、测验或 Ask Me 证据。
2. 每条标注绑定用户、学习运行、小节、确切 `ContentVersion`、正文块、文字引用上下文和正文块快照哈希。编辑与删除采用追加式修订留痕，正式记录不静默覆盖来源版本。
3. 正文更新后不自动迁移标注。只有当前正文存在唯一、规范化后完全相同的块时，读模型才可把旧标注投影到当前块展示；投影不能改写原标注的版本归属。其余标注明示为旧版记录。
4. Ask AI Session 按用户、学习运行、小节和 `ContentVersion` 隔离。旧版答疑保留为只读历史，不能继续提问，也不能把旧块锚点或讲法偏好写入当前正文。
5. 内容反馈与阅读批注保持分离。反馈在尚未产生该正文版本的测验证据时，可以通过明确的“发送并更新本节”操作生成并采用新版本；一旦该版本已产生测验尝试，反馈仍作为事实保存，但不得静默重新生成、重绑正文与测验或重写证据链。
6. 创建标注时允许绑定用户刚刚选中的旧正文版本，但该版本必须存在于当前学习运行的小节版本沿革中。这覆盖用户选中文字后、后台反馈更新恰好先完成的竞态，同时拒绝跨用户、跨学习运行和无关版本。

## 用户界面表达

- Ask AI 保持正文选区的主操作；高亮和批注作为次级、本地阅读操作。
- 标注界面明确说明“不发送给 AI，也不改变掌握情况”。
- 旧版标注和旧版答疑使用用户可理解的“旧版正文”表达，不展示内部绑定、哈希或生成轮次。
- 会触发内容更新的反馈按钮明确写成“发送并更新本节”，并提前说明正文与验证题将一起更新、已有标注仍归属原版本。

## 最低验收

- 高亮、批注创建、编辑、删除与幂等重放；
- 无关正文版本和无权标注访问失败关闭；
- 更新正文后，改变的块保留为旧版标注，完全相同的块只做确定性展示投影；
- 新旧正文各自创建独立 Ask AI Session，旧版历史只读；
- 任一测验尝试形成后，可修正文类反馈只记录，不再发布或重绑新版本；
- 迁移覆盖全新数据库、历史数据库和 ORM 预建未来表场景；
- 真实阅读页面完成高亮、页边标记和标注列表视觉验收。
