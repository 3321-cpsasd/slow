# ADR-0018：M4 可信适应性学习与统一验收合同

- **状态**：Accepted，实现完成，等待真实模型验收
- **日期**：2026-08-13
- **关联**：ADR-0012、ADR-0014、ADR-0015、ADR-0016、ADR-0017

## 背景

M4 不是单个“多模型”功能，而是四条相互依赖的可信链路：正式测评不能自写自判；Ask Me 不能由同一调用边问边评；跨书适配必须复用稳定概念身份并把证据转成明确教学动作；章节规划必须在生产发布前完成独立范围审校。只完成其中一条，会让评分、掌握画像或后续教材继续受未受控模型输出影响。

## 决策

M4 固定为四道门禁：

| 门禁 | 权威边界 | 必须失败关闭的情况 |
| --- | --- | --- |
| M4-A 可信测评 | ADR-0016 的出题、审题、盲判和独立答案版本覆盖所有新正式选择题 | Schema 越权、同家族裁决、证据悬空、答案版本缺失或局部发布 |
| M4-B 适应性口试 | 探测模型只提问，评估模型只评价；每轮冻结探测血缘与正文证据绑定 | 评估者生成问题、独立路由不足、冻结绑定缺失或重复提交不幂等 |
| M4-C 跨书适配 | 以 `conceptRevisionId` 复用概念身份，把合格记忆映射为 `compress/connect/wake/scaffold/teach/replan` | 稳定概念分叉、无教学动作、跨书严重重复或动作未被正文执行 |
| M4-D 生产治理 | 整章独立范围审校、故障注入关闭和真实模型场景共同通过 | 未审校生产目录、相邻严重重复、故障后降级发布或部分发布 |

教学动作的权威输入是版本化学习记忆和当前 Learning Contract。`compress` 只能减少已经稳固概念的重复解释，不能降低当前目标；`connect` 与 `wake` 负责必要连接和唤醒；一个可在节内补足的前置缺口使用 `scaffold`；多个或无法在典型节时长内补足的前置缺口使用 `replan`，正文作者不得自行扩展目标。

## 验收合同

机器可读合同为 `apps/api/app/evaluation/m4_acceptance.py`，Schema 固定为 `m4_acceptance_v1`。报告必须精确包含 M4-A 至 M4-D，以及以下四个场景：

1. `trusted_assessment`；
2. `ask_me_role_separation`；
3. `cross_book_adaptation`；
4. `scope_and_fault_closure`。

单元测试或确定性 fixture 只能证明实现边界，不能单独把 M4 判为通过。每道门禁都需要真实模型证据；可信测评、口试和生产治理还需要故障演练，跨书适配需要人工复核。证据必须包含不可变 URI 和内容哈希。

以下计数必须全部为零：出题者声明答案、审题者泄露答案、同家族测评裁决、未版本化正式答案、Ask Me 评估者生成问题、Ask Me 证据缺少冻结绑定、跨书稳定身份分叉、未审校生产目录以及部分发布。

## 里程碑状态

代码、迁移和确定性回归完成只表示“实现完成”。只有 `m4_acceptance_v1` 报告满足全部证据模式、阈值与硬零约束时，才可以声明 M4 `PASS`。在真实模型运行、人工复核和故障演练完成前，状态保持“等待真实模型验收”，不能用测试通过代替里程碑通过。

## 最低验收

1. 所有新正式选择题路径共享 ADR-0016 链路，历史内容只读兼容。
2. Ask Me 探测和评估使用不同 Schema 与调用，评估排除正文作者和上一轮探测者家族。
3. 跨书不同目标只要指向同一稳定概念修订，就能消费既有合格记忆并产生教学动作。
4. 生产章节范围审校不可用或无效时失败关闭。
5. 任一硬零计数非零、必需证据模式缺失或阈值未达标，M4 报告为 `FAIL`。
