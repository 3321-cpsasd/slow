# ADR-0006：Daily Mode 是短期学习情境，不是教材深度

- **状态**：Accepted
- **决策日期**：2026-08-09
- **适用范围**：首页推荐、阅读呈现、Ask AI、学习活动与证据资格
- **关联决策**：[ADR-0001](0001-lesson-generation-v2.md)、[ADR-0003](0003-modular-monolith-boundaries.md)

## 1. 决策

Slow 增加用户级 `daily_mode = fast | slow`。它表达用户当下可投入的时间与交互情境，不表达长期学习目标的深度。课程规划使用的 `overview / deep / mastery` 继续独立存储，两者不得互相覆盖或推断。

`fast` 面向通勤、户外与碎片时间，提供约 3–5 分钟的已发布正文派生视图与短交互；`slow` 提供约 10–20 分钟的完整小节。两种模式必须绑定同一个已发布 `ContentVersion`、`LearningContractVersion` 与正式 `QuizSet`，不得生成两套事实权威、验证目标或及格标准。

## 2. 状态与审计

`user_daily_mode_states` 是每个用户唯一的当前投影；`daily_mode_events` 是只追加的切换事实。每次用户选择模式、更改持续时间或从顶部显式切换时都产生事件，并记录前后模式、持续时间、用户时区、入口、激活与到期时间、状态版本和幂等键。

持续时间只接受 `1h / 3h / 6h / today`。`today` 以用户在激活请求中声明的 IANA 时区计算到下一个本地零点，服务端固化为 UTC `expires_at`。浏览器展示时间，但不能成为有效性权威。

## 3. 活动连续性

打开小节时，服务端返回当时有效的 `daily_mode_at_start` 快照。自然到期不重排、不关闭也不替换正在进行的小节；新的学习活动重新读取当前状态。用户在顶部显式切换属于主动操作，可以立即改变当前呈现。

## 4. 内容与证据边界

- Fast 只能从已发布正文作确定性选择和呈现，不修改正文或 Learning Contract。
- Fast 短互动只产生参与事实，不能解锁下一节或提高概念掌握度。
- 用户无论从 Fast 或 Slow 进入正式测验，都提交同一个 QuizSet，并由同一服务端规则评分；只有正式测验结果可以进入既有解锁和掌握证据链。
- Ask AI 可以按模式改变篇幅、结构和例子密度，但仍绑定原小节与内容块，不能增加正式教学目标，也不能替用户完成测验。
- 模式状态、派生视图和前端缓存都不得反向写入教材、测验答案或掌握投影。

## 5. 模块边界

`learning.daily_mode` 是状态和审计的唯一写入者。课程、Tutoring、首页和读模型只通过窄接口读取有效模式；它不是新的产品层级，也不引入独立服务或数据库。
