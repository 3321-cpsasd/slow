# ADR-0004：真实课程基准、候选知识图与覆盖门禁

- **状态**：Accepted，首个发布纵向切片已通过 M2
- **决策日期**：2026-08-09
- **适用范围**：培养方案/课程大纲导入、Series 规划、章目标覆盖
- **关联决策**：[ADR-0002](0002-curriculum-planning-boundaries.md)

## 1. 决策

Slow 不再用固定书数、章数、小节数或知识节点数代表课程完整性。平台先建立绑定具体院校、专业、年份和课程版本的课程基准，再把基准目标投影为个性化教材。

课程基准分为两种状态：

- `candidate`：允许保存 AI/规则提取结果、来源定位、候选概念关系和显式缺口，但不能进入正式规划；
- `published`：所有来源和候选关系已经人工复核、没有阻断型缺口，才允许被 Series 规划选择。

候选包与人工审核决定是两个独立、可审计对象。审核清单冻结候选内容摘要，逐一记录来源接受、候选关系接受或拒绝、每个显式缺口的处置阶段，以及平台自定义的开放能力量规。拒绝的候选关系不会进入发布图；审核不能静默改写候选包或删除原始缺口。

首个包采用北京大学计算机科学与技术专业 2025 级培养方案，以及北京大学选课系统中课程号一致的《程序设计实习》课程大纲。培养方案确定课程的专业核心必修地位、学分、学时和学期；课程大纲确定目标、主题课时、考核比例和指定教材。人工审核明确接受“精确课程号一致但大纲生效年份未知”为持续披露的适用性风险；指定教材只记录课程元数据，算法事实改由可公开审计且采用 MIT 许可的 OpenDSA 版本支持；代码能力采用明确标记为 Slow 平台规则的评分量规，不冒充北大官方政策。

## 2. 权威对象

```text
CurriculumSourceVersion
  └─ ProgramVersion
       └─ CourseVersion
            ├─ Competency
            └─ CurriculumBaselineVersion
                 ├─ objectives
                 ├─ concepts
                 ├─ candidate relations
                 └─ explicit gaps

SeriesCurriculumBaselineBinding
  └─ ChapterCurriculumObjectiveBinding
```

关系数据库仍是权威来源。课程范围候选保存在经过严格 Schema 校验的版本化 `graph_json` 中；经独立人工清单审核的知识事实物化为稳定 `ConceptRevision`、`LearningObjective`、类型化关系、主张、来源绑定和 `KnowledgeGraphRelease`，不需要引入图数据库。候选导入不能直接发布平台知识事实。

## 3. 规划门禁

规划前只检索 `published` 基准，并把确定版本、课程目标、能力、概念候选、来源范围和考核要求放入生成上下文。

模型为每个章返回 `baseline_objective_ids`。服务端在保存 LearningPlan、Series、Book 或 Chapter 之前确定性校验：

- 绑定目标必须全部属于当前基准；
- 每个 `required` 基准目标至少由一章承载；
- 未知目标或覆盖缺失整批失败；
- 不校验最少概念节点数、固定章数或每章固定小节数。

通过后，Series 冻结采用的基准版本及内容摘要；章分别保存目标绑定。后续生成读取相同绑定，新的课程基准版本不能静默改变已经开始的教材。

规划还必须为已发布知识图返回精确 `baseline_concept_ids`。服务端校验概念与章目标属于同一个已发布绑定，并把 release、concept revision、learning objective pair 冻结到章级知识身份范围。小节只能从该章范围返回稳定双键；不能把同一宽泛课程目标关联的所有概念机械复制到每一章，也不能从章标题猜概念。

## 4. 来源与审核边界

每个课程来源必须保存权威机构、URL、版本标签、发布日期、适用院校/专业、检索日期、内容摘要和提取方式。摘要当前只覆盖规范化提取字段，不伪装成完整网页归档。

以下情况必须保留显式缺口，并按影响阶段分别处置：

- 培养方案和课程介绍无法证明属于同一适用版本；
- 指定教材或知识事实支持缺失；
- 开放能力缺少评分标准；
- AI 推断的前置、组成、对比或应用关系尚未人工复核。

课程大纲生效版本不明可以在人工确认精确课程号关联、同时持续声明版本未知后作为有记录的适用性风险接受；这不等于把大纲改称为某一年版。指定教材正文缺失阻断知识事实发布，但不阻止仅由培养方案和课程大纲直接支持的课程范围发布。代码量规缺失阻断能力证据；Slow 可以采用明确标记为平台规则的量规，但不得冒充院校官方考核政策。

URL 可达只证明页面能够访问，不证明课程仍适用、知识主张正确或关系成立。

## 5. 首个切片的边界

当前交付证明：

- 官方来源可以导入为不可静默覆盖的候选版本；
- `Discipline`、`ProgramVersion`、`CourseVersion` 和 `Competency` 有独立权威身份；
- 候选基准不能被规划器选择，独立人工审核清单必须冻结内容摘要并逐项覆盖；
- 人工复核后的北大基准可以驱动按目标覆盖的规划；
- 目标遗漏和基准外目标在正式数据持久化前失败关闭；
- 完整规划覆盖八个目标，不要求固定节点或章数；
- 章级稳定概念范围、小节双键和 Learning Contract 形成同一发布版本链。

北大课程基准与“递归—图搜索—动态规划”知识薄切片已在隔离 M2 验收库中完成人工审核发布；这不等于写入生产数据库，也不把指定教材伪装成已核验正文。
