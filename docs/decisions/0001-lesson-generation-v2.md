# ADR-0001：小节正文与测验的一次生成及原子发布

- **状态**：Accepted，正文与补救题的权威发布边界已落地；旧生成适配器待观测期后清理
- **决策日期**：2026-08-06
- **适用范围**：小节规划完成后，从正文生成到正式发布的在线链路

> V3 继续继承本文的一次调用、Learning Contract、稳定绑定、失败关闭和原子发布边界；第 6 节的固定共享槽位仅保留为 V2 历史协议，已由 [ADR-0009](0009-adaptive-lesson-composition.md) 的动态正文编排取代。
- **上位产品约束**：[Slow 产品底层基因](../../PRODUCT_DNA.md)

## 1. 为什么需要这项决策

当前正文生成依次执行教学蓝图、正文生成、来源检查与修复、独立测验生成、同模型语义复核、主张核验和发布。它带来三个根本问题：

1. 多次串行模型调用让首次正文通常需要 1–2 分钟；
2. 同一模型自写自审不能构成可靠的独立事实核验，却容易让产品和开发者误以为内容已经被证实；
3. 实时抓取公开网页、保存、发送给第三方模型再改写，会额外引入著作权、网站条款、付费墙、自动访问和数据处理风险。

现有链路同时混淆了两类不同问题：

- **内容是否教对、教好**是概率性质量问题，主要依靠模型能力、上下文设计、离线评测和真实学习反馈持续改进；
- **内容是否越权考核、污染证据**是确定性边界问题，必须由服务端规则强制保证。

本决策把两类问题分开处理，不再把多跑几次同模型包装成可靠治理。

## 2. 决策摘要

小节在线生成采用以下默认路径：

```text
冻结的 Mission + 小节学习锚点 + Learning Contract
          + 相邻小节边界 + 精简的相关掌握证据
                              ↓
                    一次强模型调用
                正文 + 测验 + 局部绑定
                              ↓
                    服务端确定性校验
                              ↓
                       原子保存并发布
```

从默认在线链路中删除：

- 独立教学蓝图调用；
- 实时网页抓取；
- 来源 URL 修复；
- 独立测验生成；
- 同模型语义自审；
- 全文逐条主张核验。

默认路径只进行一次物理模型调用。结构或契约校验失败时，整批候选结果作废；系统可以执行有上限的整批重新生成，但不得局部修补、摘除坏题后发布，也不得重新引入常态化的第二次语义审核。每次重新生成都是独立的 `GenerationAttempt`，必须记录失败原因、模型版本和成本。

## 3. 不可破坏的产品与教学边界

### 3.1 产品层级止于小节

```text
用户 → 书架 → 系列（学习目标） → 书 → 章 → 节
```

内容块只是节内结构，没有独立目录、编号、进度或解锁状态。定义、机制、例子、边界、练习、小结和自测等教学阶段不能仅凭形式成为并列小节。

### 3.2 小节是单一学习锚点，不是孤立知识节点

每节只有一个核心知识点和主要验证问题。正文可以调用与该锚点存在明确教学关系的局部知识子图，包括：

- 必要前置知识；
- 机制依赖；
- 相近概念与对比；
- 适用边界和反例；
- 应用与迁移知识；
- 合格学习证据显示薄弱的关联知识。

已经有合格掌握证据的关联知识只做必要连接；薄弱或缺失的关联知识增加解释和脚手架。“知识子图”在 MVP 中只是生成上下文和内容块关系，不引入图数据库，也不形成新的产品层级。

### 3.3 大型前置缺口必须退出正文生成

如果某个前置缺口无法在不新增并列考核目标、且不破坏本节典型投入的情况下补足，正文生成必须失败并返回：

```text
PREREQUISITE_GAP_REQUIRES_REPLAN
```

后续由显式规划或重规划流程增加正式前置小节。正文生成器无权自行扩展课程结构或 Learning Contract。

### 3.4 Learning Contract 是考核边界的唯一权威

内容块必须与本节核心知识锚点存在可解释的教学关系。关联知识可以用于解释，但除非显式加入并版本化当前 Learning Contract，否则不得：

- 写入正文块的可考核目标绑定；
- 进入测验；
- 形成掌握证据；
- 因为正文曾经讲过而被推断为用户已经掌握。

Learning Contract 必须在正文生成之前冻结。生成器不能创建目标、修改目标、降低门槛或把相似自然语言自动映射成另一个目标。

## 4. 生成职责边界

### 4.1 课程规划负责

- 决定系列、书、章和小节；
- 为每节确定一个核心知识锚点和主要问题；
- 创建并版本化 Learning Contract；
- 给出前后相邻小节的范围边界；
- 在大型前置缺口出现时重规划未来内容。

### 4.2 模型负责

- 围绕核心锚点组织完整正文；
- 根据相关掌握证据压缩或展开关联知识；
- 一次生成正文、测验和候选局部绑定；
- 让测验只测量输入中已经冻结的目标。

模型输出是候选结果，不是权威事实，也没有发布资格。

### 4.3 服务端确定性校验负责

- 校验 JSON Schema；
- 校验稳定目标 ID 的成员关系；
- 校验正文块、题目和局部引用完整性；
- 校验所有必需目标的正文与测验覆盖；
- 拒绝任何契约外目标和悬空引用；
- 保证失败候选不进入正式内容、题集、进度或掌握证据。

确定性校验不负责证明事实正确、解释充分、答案在语义上正确或题目没有歧义。

### 4.4 离线质量体系负责

- 事实准确性和答案正确性评测；
- 教学完整性、清晰度和难度评测；
- 正文是否真正支持题目答案的语义评测；
- 按模型、Prompt、Schema、主题和难度进行版本对比；
- 用用户纠错、重新生成和延迟学习表现推动迭代。

离线评测结果不能反向伪造某个在线内容版本已经经过逐项事实核验。

## 5. 一次生成的权威输入

服务端构造一个精简、版本化的 `LessonGenerationSpec`。至少包含：

- Mission 版本和本节目的；
- 小节核心知识锚点与主要问题；
- 冻结的 Learning Contract 版本；
- 契约内每个目标的稳定 `assessment_target_id`；
- 前后相邻小节的边界摘要；
- 只与当前锚点相关、且来源合格的掌握证据摘要；
- 学习深度策略；
- `model_only`、`rights_grounded` 或 `demo` 生成模式；
- 若为 `rights_grounded`，服务端审核通过的知识资产版本 ID；
- 模型、Prompt、Schema 和上下文策略版本。

默认不提供全部画像、全部学习历史、整本书正文或未经筛选的长期记忆。用户文字始终是数据，不是能够覆盖服务端契约的指令。

## 6. 候选输出与绑定协议

在线模型先返回最小化的 `GeneratedLessonSlotCandidate`。服务端按冻结目标顺序预分配
`T1`、`T2`……槽位，并在 Schema 校验后确定性展开为内部
`GeneratedLessonCandidate`。模型不再负责抄写稳定 ID、局部 Key、正文角色或证据块引用。
示意结构如下：

```json
{
  "blocks": [
    {
      "slot": "T1_CORE",
      "kind": "text",
      "heading": "为什么会出现这个结果",
      "content": "……"
    },
    {
      "slot": "SHARED_EXAMPLE",
      "kind": "bullet_list",
      "heading": "把判断放进真实场景",
      "content": "先观察几个稳定对象：\n\n- 对象 A 满足条件。\n- 对象 B 缺少条件。\n\n再比较它们产生的结果。"
    }
  ],
  "questions": [
    {
      "target_slot": "T1",
      "prompt": "……",
      "options": ["……", "……", "……", "……"],
      "correct": [1],
      "explanation": "……"
    }
  ],
  "feedback_replacement_slot": "T1_CORE"
}
```

约束如下：

- 每个服务端目标槽位必须且只能对应一个 `Tn_CORE` 块；
- `SHARED_EXAMPLE`、`BOUNDARY`、`PRACTICE`、`SUMMARY` 是固定共享槽位，
  `PREREQUISITE` 与 `TRANSITION` 只能按需出现；
- `target_slot` 只能引用服务端预分配槽位，题目由服务端绑定到同名 `Tn_CORE`；
- `assessment_target_id`、`block_key`、`item_key`、正文角色、锚点关系与
  `evidence_block_keys` 全部由服务端确定性派生，模型不得输出；
- 服务端只在全部校验通过后分配正式的内容块版本 ID 和测验题 ID；
- `assessment_eligible`、目标规范文案、必需性和 `core` 等权威字段由服务端根据冻结契约派生，不信任模型布尔值；
- 共享与支撑槽位不直接获得考核目标；只有 `Tn_CORE` 获得同序目标绑定；
- 服务端展开是版本化槽位协议的权威派生，不是对模型自由文本的猜测或修复；计划外、缺失或重复槽位整批失败；
- `content` 始终是 GFM Markdown，可以在同一内容块中自然混合段落、并列列表、有序步骤与表格；
- `kind` 只作为主要展示方式和界面标签的非权威提示，`text` 是通用回退值；服务端不得因为
  `kind` 与 Markdown 结构不同而拒绝、重写或重新生成可正常渲染的候选；
- 服务端仍确定性限制空内容、重复标题、未分段的长篇纯正文和过长纯正文段落；这些检查只处理
  明确影响发布或阅读的结构，不以展示提示代替内容格式；
- 反馈触发完整重生成时，模型必须返回真正替代旧块的
  `feedback_replacement_slot`；服务端再把冻结的旧 `source_block_id` 与新槽位展开出的
  `replacement_block_key` 显式绑定。非反馈生成该字段必须为空。

选择题发布前，服务端对选项执行确定性的均衡重排并同步重映射正确答案索引；模型解释不得依赖
`A/B/C/D` 或选项位置。该派生只改变展示顺序，不改变题义、答案内容、目标或正文证据绑定。

内容块角色和锚点关系是节内教学属性，不是目录层级；它们由服务端根据槽位协议派生并版本化。

## 7. 确定性发布门禁

以下门禁全部通过后才允许发布：

| 门禁 | 失败行为 | 建议错误码 |
| --- | --- | --- |
| 候选结果满足版本化 JSON Schema | 整批失败 | `GENERATION_SCHEMA_INVALID` |
| 正文块局部 Key 唯一且合法 | 整批失败 | `CONTENT_BLOCK_KEY_INVALID` |
| 正文块非空、不重复标题，长篇纯正文满足版本化分段规则 | 整批失败 | `CONTENT_BLOCK_LAYOUT_INVALID` |
| 正文块绑定目标全部属于冻结契约 | 整批失败 | `CONTENT_ASSESSMENT_TARGET_UNBOUND` |
| 题目目标属于冻结契约 | 整批失败 | `ASSESSMENT_TARGET_UNBOUND` |
| 题目引用的正文块存在 | 整批失败 | `ASSESSMENT_EVIDENCE_BLOCK_UNBOUND` |
| 题目引用块绑定同一个目标 | 整批失败 | `ASSESSMENT_EVIDENCE_TARGET_MISMATCH` |
| 每个必需目标至少被一个正文块教授 | 整批失败 | `REQUIRED_TARGET_NOT_TAUGHT` |
| 每个必需目标至少被一道题测量 | 整批失败 | `REQUIRED_TARGET_NOT_ASSESSED` |
| 选项、正确答案索引和题数结构合法 | 整批失败 | `ASSESSMENT_ITEM_INVALID` |
| 大型前置缺口不被塞进当前小节 | 进入显式重规划 | `PREREQUISITE_GAP_REQUIRES_REPLAN` |
| 反馈重生成缺少、错配或悬空的块替换映射 | 整批失败 | `FEEDBACK_REPLACEMENT_MAPPING_REQUIRED` / `FEEDBACK_REPLACEMENT_SOURCE_MISMATCH` / `FEEDBACK_REPLACEMENT_BLOCK_UNBOUND` |

错误响应必须包含机器可读定位，例如局部 Key、非法目标 ID 和契约版本。任何门禁失败都发生在正式内容持久化之前。

服务端可以执行的权威派生不属于自动修正，例如：

- 根据契约 ID 写入规范目标文案；
- 根据契约绑定派生 `core` 和 `assessment_eligible`；
- 校验通过后分配数据库 ID；
- 生成可重建的哈希、版本号和审计投影。

服务端不得：

- 按自然语言相似度猜测目标；
- 把非法目标替换成最接近目标；
- 丢弃坏题后发布剩余题目；
- 静默删除契约外正文绑定；
- 降低目标难度或通过门槛以使候选结果通过。

## 8. 状态、权威来源与原子发布

生成尝试和正式内容必须是两个不同的权威对象。

```text
GenerationAttempt
generating → validating → succeeded
                      ↘ failed
```

`GenerationAttempt` 保存运行审计、错误码、模型与规则版本、用量和不含密钥的必要诊断信息。为了排障保存的失败候选只能位于隔离审计存储，不能成为正文权威记录，也不能被普通用户读取。

只有候选结果通过全部门禁后，服务端才在一个数据库事务中创建：

- `ContentVersion(published)`；
- 与其绑定的正式内容块版本；
- `QuizSet(published)`；
- 正文块到契约目标的绑定；
- 测验题到契约目标和正文块的绑定；
- 当前发布版本指针或等价权威状态。
- 首次进入阅读和后续证据链所必需的学习实例版本绑定。

上述必要记录以及 `GenerationAttempt=succeeded` 必须由同一次提交完成。提交成功即形成不可否认的发布事实；提交后的读模型组装、响应序列化或其他展示失败不得再把该运行改写为 `failed`。

正式内容版本的生命周期独立于生成尝试：

```text
published → superseded
          → withdrawn
```

只有 `published` 内容可以进入阅读、测验、解锁和学习证据链。数据库中存在一行记录、生成任务完成或 URL 可达，都不等价于内容已发布或事实已核验。

事务失败时不得产生部分正文、孤立题集、进度变化或掌握证据。失败调用审计可以单独持久化。

### 8.1 补救题沿用同一发布边界

补救生成可以暂时复用兼容 AI 调用，但其输出只能是候选，不能直接成为题集。服务端必须以失败答题实际使用的冻结
`QuizSet`、`ContentVersion` 和 `LearningContractVersion` 为唯一源版本，并执行以下确定性约束：

- 原题集必须仍为 `published`，且最新治理决策同时满足 `allowed=true` 和
  `assessmentEligible=true`；
- 补救教学块与替代题只能覆盖该次答题失败的稳定目标，并完整覆盖全部失败目标；
- 每道替代题必须显式记录 `sourceAssessmentItemVersionId`，保持被替换原题的目标，并继承其冻结
  `evidenceBlockIds`；不得重新通过自然语言、数组位置、旧 claim anchor 或模型输出猜测正文证据；
- 被继承的正文块必须属于原答题的冻结正文版本，并明确教授同一稳定目标；
- 全部门禁通过后，新的 `QuizSet(published)`、`AssessmentItemVersion`、证据块绑定、
  `Remediation`、治理快照和成功运行审计在同一事务中提交。

任何补救候选校验失败都整批回滚。普通读模型不得展示候选或治理拒绝的题，提交入口也必须再次检查发布状态与
最新治理资格；不合格题不能评分、解锁或写入任何掌握度、保持度与门槛投影。

## 9. 生成模式、版权与可信表达

Slow 不建设“全网来源包”，不在默认在线请求中抓取公开网页全文。

允许的生成模式为：

- `model_only`：默认模式，只使用模型、冻结契约和精简学习上下文；
- `rights_grounded`：只使用 Slow 自有、购买授权、用户有权使用且隔离保存、公有领域、CC0 或经人工审核确认兼容的材料；
- `demo`：显式隔离的演示或开发数据，不能伪装成真实 AI 内容或正式学习证据。

许可不明、限制商业使用、禁止改编、付费墙或限制自动抓取的材料默认不进入知识底座。许可必须绑定具体作品版本和审核记录，不能只绑定网站名称。

用户侧可信表达应明确区分生成方式、权利状态和事实状态。默认文案为：

> AI 生成，并已通过结构、契约和证据边界校验；未经逐项事实核验。

不得把以下事实表述为“内容已经核验”：

- Schema 合法；
- 数据库存在记录；
- 来源 URL 可访问；
- 同一模型给出通过意见；
- 离线同类样本总体表现良好。

医学诊疗、法律意见、金融建议、当前政策及其他高风险或强时效主题，MVP 默认不进入正式可信教材生成路径。只有产品策略明确允许，且接入权利清晰、可靠并带版本日期的知识底座后，才能提供更强可信声明。

## 10. 重试规则

一次调用是默认路径，不是禁止任何失败恢复的教条：

- OpenAI 兼容端点的默认正文 one-shot 调用显式关闭 provider thinking；结构可靠性由槽位协议和服务端门禁承担，不用 Prompt 软约束或小型推理预算充当质量门；
- 保留宽松的最终输出 token 保险，仅用于终止异常失控，不作为教学质量调节器；
- 第一次物理调用返回完整候选结果；
- 确定性校验失败时整批作废；
- 系统可以进行配置化、有上限的整批重新生成；
- 每次重试创建新的 `GenerationAttempt`，记录触发错误；
- 重试不能复用失败结果的一部分，也不能只修题、只修字段或由第二次调用批准第一次结果；
- 线上不得静默回退到旧的多阶段生成流水线。

具体重试上限属于运行配置，但必须有限、可审计，并纳入延迟、失败率和单位发布成本指标。

## 11. 衡量指标

产品结果指标：

1. 首版可用率；
2. 首版经确认的“不准确”反馈率；
3. 首版重新生成率；
4. 点击到正文的 P50/P95 时间；
5. 首次测验表现；
6. 延迟复习保持率；
7. 迁移题表现；
8. 版本后悔率：发布后因内容质量问题被纠错、替换或撤回的比例。

运行护栏指标：

- Schema 失败率；
- `CONTENT_ASSESSMENT_TARGET_UNBOUND` 和 `ASSESSMENT_TARGET_UNBOUND` 等绑定违规率；
- 整批重试率与最终失败率；
- 每个成功发布小节的模型调用次数和成本；
- 按模型、Prompt、Schema、主题、难度和生成模式分层后的质量结果。

首次测验高分不能单独证明正文质量，必须结合题目难度、用户纠错、延迟保持和迁移表现解释。

## 12. 实施顺序

实现必须按以下顺序推进：

1. 固定 `LessonGenerationSpec`、`GeneratedLessonCandidate` 和错误响应 Schema；
2. 先实现纯函数式确定性校验器及正常、失败和原子性测试；
3. 分离 `GenerationAttempt` 与正式 `ContentVersion` 的状态和写入边界；
4. 在 AI Port 中新增一次调用的 `generate_lesson` 能力；
5. 为真实供应商和显式 Demo 适配器实现同一契约；
6. 实现单事务发布和只读取 `published` 内容；
7. 以显式管线版本灰度 `lesson_generation_v2`，不得静默回退旧链路；
8. 用离线样本比较首版质量、延迟、成本和绑定违规；
9. 达到退出条件后，删除教学蓝图、实时来源修复、独立测验、同模型复核和实时主张核验的在线调用；
10. 保留旧内容和旧审计记录的只读兼容，不把历史治理数据改写成新可信声明。

实现仍在现有 FastAPI 单体中完成，不引入微服务。推荐在应用层收敛为：

```text
build_generation_spec()
        ↓
ai.generate_lesson()
        ↓
validate_candidate()
        ↓
publish_atomically()
```

## 13. 最低验收测试

实现完成前至少覆盖：

- 一次生成只发生一次物理模型调用；
- 长篇纯正文未分段或单段过长时整批失败；
- 同一 Markdown 内容块可以混合短段落、并列列表、有序步骤和表格，且不会因 `kind` 提示不同而失败；
- 正文绑定契约外目标时整批失败；
- 题目引用契约外目标时整批失败；
- 题目引用不存在的正文块时整批失败；
- 题目引用未绑定同一目标的正文块时整批失败；
- 必需目标缺少正文覆盖时整批失败；
- 必需目标缺少测验覆盖时整批失败；
- 大型前置缺口进入显式重规划；
- 任一校验失败后没有正式正文、题集、进度或学习证据；
- 发布事务中途失败不会产生部分可用内容；
- 普通读取接口无法读取失败候选、`superseded` 或 `withdrawn` 内容；
- 整批重试产生独立、可审计的 `GenerationAttempt`；
- 用户纠错生成新版本，不静默覆盖旧版本；
- `model_only`、`rights_grounded` 和 `demo` 在数据与用户界面上可区分。

## 14. 明确不做什么

本决策不授权：

- 建设实时全网爬虫或 NotebookLM 式公开网页来源包；
- 把内容块升级为目录、编号或解锁层级；
- 为“知识子图”提前引入图数据库；
- 允许正文生成器自动扩展 Learning Contract；
- 用同模型自审替代独立事实依据；
- 用免责声明放行原本不支持的高风险正式教材；
- 为这次重构引入新的微服务。

## 15. 决策结果

这项重构不是削弱治理，而是用严格的权威边界、可审计版本和真实效果评估，替换昂贵但不能证明事实正确的概率型在线审核。

最终目标是：

> 用一次高质量生成完成正文、测验和显式绑定；用确定性规则保证契约边界、引用完整性和原子发布；用离线评测与真实学习结果持续提高事实准确性和教学质量。
