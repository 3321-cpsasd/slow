# ADR-0014：用途感知的 AI Harness 与模型部署网关

- **状态**：Accepted，第一阶段已实现
- **日期**：2026-08-13
- **范围**：正文生成、Ask AI、Ask Me、内容反馈、运行时 AI 配置与调用审计

## 背景

此前所有 `AiPort` 操作共享一个主模型和同一备用链。Prompt 虽然不同，但调用方无法表达任务权限、能力要求和作者血缘；正文作者因而可能回答围绕该正文的问题、评估自己的教学结果并根据“不准确”反馈直接改写自己的输出。确定性校验能约束结构、Learning Contract 与引用绑定，但不能把模型自评变成事实证据。

问题不等于“相同模型绝不能承担多个用途”。Ask AI 只产生临时回答，本身不写入正文或掌握证据；真正需要强制独立的是会影响发布内容或掌握画像的判断。模型池也不等于 fallback 列表：前者描述部署事实，后者只是某个用途的有序路由策略。

## 决策

在业务 Harness 与供应商 Adapter 之间增加用途感知网关。正文仍遵守 ADR-0001 的 Learning Contract、稳定绑定、确定性校验和原子发布边界；测评生成改由 ADR-0016 的异构职责链负责，不增加在线同模型语义自审。

### 1. 上层 Harness 声明任务，不声明供应商模型

每次调用由网关构造 `AiTaskEnvelope`，至少包含：

- `purpose`：课程规划、正文作者、Ask AI、反馈修订、评估探测或评估判定等稳定用途；
- `authority`：临时回答、待校验候选、掌握证据候选或系统审计；
- `requirements`：结构化输出、流式输出等硬能力；
- `lineage`：作者部署、作者模型家族以及是否必须排除作者家族。

调用方仍拥有业务 Prompt、JSON Schema、Learning Contract、确定性校验和发布权限。网关只选择满足约束的部署，模型输出始终只是候选结果。

第一阶段通过显式实现全部 `AiPort` 操作消除默认透传；供应商无关 Prompt Harness 的物理抽取可以继续进行，但不得改变本 ADR 的任务边界。

### 2. 下层使用部署注册表与版本化用途路由

`ModelDeployment` 使用稳定 `deploymentId`，并显式记录：

- `providerId`、精确 `model`、显式 `modelFamilyId`；
- 协议、API 形态、结构化输出模式与流式能力；
- `backendAllowed`、允许环境和运行状态；
- 服务端 Base URL 与密钥。

新配置不得依靠模型名猜测家族；名字推断仅用于旧配置兼容。路由引用部署 ID，并记录 `configVersionId` 与 `routePolicyVersion`。未知部署、当前环境没有获准部署或缺少必需能力时失败关闭，不静默退回全局默认模型。

发布显式模型池配置前，服务端检查所有已路由部署的连接；未路由候选应保持隔离或禁用状态。连接成功不等于教材质量合格，质量准入仍由离线评测决定。

仅获准在交互式 Harness 中使用的订阅不能进入生产后端模型池。第三方模型列表只可作为候选发现信息；在生产启用前必须单独确认后端调用授权、接口可用性、结构化与流式行为、超时限流和质量评测。

### 3. 按决策权设置独立性边界

- **正文生成**：走 `lesson_author`；发布仍受 ADR-0001 门禁约束。
- **Ask AI**：走 `ask_ai`，权限为临时回答；可以与作者同家族，但不能写正文、测验或掌握证据。
- **Ask Me 探测问题**：走 `assessment_probe`，Schema 只允许返回维度与问题，不能评价学习者答案。
- **Ask Me 评估**：走 `assessment_evaluation`，Schema 只允许返回上一答复的评价、理由与证据充分性，不能生成下一题。它会形成掌握证据，因此必须取得已发布正文作者和上一轮探测者的冻结血缘，并排除两者部署及整个模型家族；血缘缺失或无独立候选时失败关闭。网关在评估完成后再独立路由下一轮探测。
- **表述类反馈**（错字、未讲清、例子、排版）：走 `feedback_style`，可由作者家族修订，但结果仍需完整生成、确定性校验与原子发布。
- **准确性反馈**：不得直接触发模型改写，先进入 `needs_review`；原正文保持不变，直至具备独立来源证据或人工复核结论。
- **其他反馈**：先分类，分类前不得自动改写。

换一个模型只能降低关联错误，不能被表述为事实核验。

### 4. 失败切换不能跨越输出或校验边界

结构化候选可在完整候选被 Harness 拒绝后尝试下一个合格部署，但不能降低 Schema 或业务校验门槛。流式调用只允许在尚未产生任何输出时切换；一旦输出首个 delta，后续故障直接中断，禁止拼接不同模型的回答。

## 配置与兼容

Runtime Settings schema 升级为 v4，增加部署池、用途路由及配置版本。v1–v3 继续可读；旧的单主模型和 fallback 配置会转换为兼容部署，但新配置必须显式声明稳定部署身份、能力和授权范围。API Key 只保存在服务端，运行时状态仅返回是否已配置密钥。

`AI_MODEL_POOL` 是旧 `AI_FALLBACK_MODELS` 的兼容别名。环境变量路径保留用于 MVP 启动，但用途路由的权威配置仍是版本化 Runtime Settings。

## 审计

每个物理供应商请求写入 `AiInvocation`，记录：

- purpose 与 authority；
- deployment ID 与 model family ID；
- config version、route policy version 与 fallback index；
- 原有的供应商、模型、用量、主体归属和结果状态。

`GenerationRun.trace_json` 同时记录实际模型尝试、部署、家族和路由版本；后续反馈与 Ask Me 必须从已发布 `ContentVersion` 的生成运行读取作者血缘，不能依赖当前默认模型。

## 验收条件

- 上层调用接口不接触供应商模型 ID，Ask AI 可独立路由；
- 结构化与流式能力在路由前硬过滤；
- 生产环境拒绝未声明 `backendAllowed` 的部署；
- Ask Me 探测与评估的 Schema 不共享权限，评估排除正文作者和上一轮探测者家族，血缘缺失时失败关闭；
- 准确性与未分类反馈不发布新正文；
- 表述类反馈保留原有确定性校验和原子发布；
- 流式响应不会跨模型拼接；
- Runtime Settings v1–v4 可安全读取，v4 可往返保存部署池与路由；
- 迁移后每个物理调用具备用途、部署和配置版本审计字段。

## 后续

- 把业务 Prompt 与 Schema 进一步抽取为供应商无关 Harness 组件；
- 增加部署能力探测的时间戳、隔离状态与定期复测；
- 建立离线教材、答疑和评估基准，路由只消费已发布评测结果；
- 为准确性反馈建设来源证据或人工复核队列，而不是重新引入模型自审。
