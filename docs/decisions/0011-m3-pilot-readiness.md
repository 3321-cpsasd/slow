# ADR-0011：M3 可靠、可诊断、跨知识类型适配的教材闭环

- **状态**：Accepted，实施中
- **决策日期**：2026-08-12
- **适用范围**：正式试点路线连续性、错因诊断、补救有效性、正文质量、学习偏好与 M3 退出判定
- **继承边界**：[ADR-0001](0001-lesson-generation-v2.md)、[ADR-0005](0005-m2-acceptance-v2.md)、[ADR-0008](0008-section-continuity-and-recovery.md)、[ADR-0009](0009-adaptive-lesson-composition.md)

## 1. 里程碑定义

M3 证明 Slow 能在不改变 Learning Contract、验证难度和证据门禁的前提下，为正式试点路线持续交付跨知识类型正文，并根据可审计的错误证据提供有针对性的补救。

M3 不包含 Ask Me 深度适配和跨书个性化；它们属于 M4。30 人完成、保持、留存和成本属于 M6。

## 2. 模型故障的透明失败与恢复

Slow 是依赖生成模型完成教材生产的 Agent。全部生成模型不可用时，允许当前内容准备失败；M3 不要求用预制内容掩盖模型失效，也不承诺模型不可用时仍能继续首次生成。

模型故障必须失败关闭：候选正文、题集和绑定不得部分发布，任务不得伪装成功，用户必须看到“AI 本次未完成生成”、影响范围和可执行的重试入口。开发者必须能够从不含原始输出与敏感信息的运行审计中定位供应商、阶段、安全错误码和重试结果。模型恢复后，同一任务必须可以安全重试，不产生重复版本或绕过发布门禁。

系列分为：

- `recoverable`：正式试点默认路线。保留模型回退、任务恢复与用户重新准备；供应商全部失效时明确失败，恢复后安全重试；
- `guaranteed`：可选的预制内容保障能力。只有确实需要离线内容连续性的路线才启用，并要求全部可激活小节绑定与契约语义签名精确匹配的已发布标准内容包。

标准内容匹配必须覆盖稳定目标 ID、required、verification policy、目标深度、前置与边界、知识版本、语言和适用范围。禁止按标题相似度或自然语言模糊映射。

标准内容不是 M3 前置条件，也不是门禁旁路。启用时仍须通过正文、题集、目标、证据和原子发布校验；未启用标准内容不得被报告为 `guaranteed`。

## 3. 五类错因与拒绝诊断

冻结以下内部错因代码：

- `prerequisite_gap`：缺少理解当前目标所需的前置；
- `concept_confusion`：定义、对象或类别混淆；
- `mechanism_reasoning_break`：机制、因果链或推导步骤断裂；
- `boundary_comparison_error`：条件、例外或相邻概念差异判断错误；
- `application_transfer_failure`：能够识别或复述，但不能用于新情境。

`insufficient_evidence` 是拒绝强行诊断的状态，不是第六类错因。单题错误不足以支持明确结论时必须使用该状态。

诊断由服务端基于不可变题目版本、被选干扰项的受控标签、目标维度、前置关系和历史观察确定。模型可以生成补救内容，但不得自由创造诊断身份。

## 4. 补救边界

补救策略由诊断决定，不再按补救次数轮换。补救仍绑定原答题使用的冻结正文、题集和 Learning Contract，完整覆盖失败目标，并使用同等难度的新题验证。

错因只用于选择教学动作，不形成新的 Assessment Target，不直接写入掌握结论，也不向普通用户展示内部枚举。

## 5. 跨知识类型覆盖

M3 真实模型评测覆盖五种认识方式：形式与定量、技术与过程、科学与因果、文本与历史解释、社会实证与规范案例。每类至少覆盖概念、机制、边界和迁移四种任务，共不少于 20 节。

真实案例与原始材料必须绑定允许主张；没有允许主张时只能使用明确标记的假设情境。worked example、反例或迁移情境描述教学用途，正文仍必须明确其事实或假设边界，不能借用途标签暗示未经绑定的真实事实。

## 6. 学习偏好授权

系统可以从请求、反馈和采用行为生成 `suggestedPreferences`，但只有用户明确确认的 `confirmedPreferences` 才能进入后续生成上下文。

“有帮助”和“保留为当前段落的另一种讲法”都不等价于长期确认。用户必须执行明确的“以后优先这样讲”操作，且可以按全局或书架范围撤销。

偏好只影响开场、密度、例子和表现形式；不得改变目标、事实、答案、难度、及格线和掌握证据。

## 7. M3 硬门禁

零容忍：契约外目标、悬空正文证据、部分发布、锁定内容泄露、补救降难度、偏好改变目标、无主张真实案例、模型失败伪装成功、契约错配 fallback 和学习门禁绕过均为 0。

最低质量阈值：

- 正文与补救候选在允许重试内成功发布率均不低于 90%；
- 五类错因 macro accuracy 不低于 80%，任一类别不低于 70%；
- 应拒绝诊断时返回 `insufficient_evidence` 的比例不低于 90%；
- 补救后同目标恢复率不低于 70%；
- 跨类型人工评分平均不低于 80/100，任一类型不低于 75/100；
- 已确认且适用的偏好正确进入内容编排比例不低于 85%；
- 模型故障被明确告知且不产生部分发布的演练通过率为 100%；
- 模型恢复后的安全重试演练通过率为 100%。

## 8. 机器判定与证据

M3 报告必须包含 `M3-A` 故障透明与恢复、`M3-B` 诊断、`M3-C` 补救、`M3-D` 正文质量和 `M3-E` 偏好五组门禁。未知、重复、缺失或无证据的门禁拒绝解析；任一 `fail` 或 `not_run` 都使整体结果为 `FAIL`。

样本必须在运行前冻结，失败样本不能从分母中删除。确定性 Fixture 只能验证工程合同，不能冒充真实模型、人工审核或学习效果证据。

证据模式同样是门禁：`M3-A` 必须包含模型故障演练，`M3-B` 必须包含人工标注真值，`M3-C` 与 `M3-E` 必须包含正式试点观察，`M3-D` 必须同时包含真实模型运行和人工评分。由此，安全部署是收集 M3 试点证据的前提，不等于部署前已经通过 M3，也不能用 Fixture 把试点结果提前写成 `PASS`。

本口径使用 `m3_acceptance_v2`；旧版把预制 fallback 当成必需连续性能力，不得在新口径下直接复用为通过证据。
